# ADR-007 — Implementation language: decided by Phase 0 spike

**Status:** pending (Phase 0 spike — dataframe-99s.3 / dataframe-99s.4)  
**Date:** 2026-07-02

## Context

Two candidate languages for the WASM kernel layer have been identified: **AssemblyScript** and **Rust**. The choice affects binary size, throughput, allocator ergonomics, string handling, toolchain friction, and how easily future AI agents can write new kernels.

## Decision

_To be filled in after the Phase 0 language spike (beads dataframe-99s.3 and dataframe-99s.4) produces benchmark data._

## Spike protocol

The spike implements the same three kernels in both languages, each with SIMD and scalar variants:

1. `add_f64` — elementwise f64 addition
2. `sum_f64_nullable` — null-aware f64 sum reduction
3. `cmp_gt_f64_to_bitmask` — comparison producing a validity bitmask (for filter)

## Decision criteria (priority order)

1. Kernel throughput (SIMD ≥ 1.5× typed-array JS baseline at 1M rows)
2. Binary size vs. ≤ 75 KB gzipped budget
3. Maintainability for agents writing many kernels

## Expected outcome (planning)

Rust is expected to win on codegen quality; AssemblyScript on binary size and toolchain simplicity. Either is acceptable behind the flat-ABI defined in ADR-008.

## Reversal clause

Any reversal of this decision after the spike merges requires a new ADR with benchmark evidence showing that the chosen language fails a gate that the other would pass.
